Vor Barcelona arbeiteten Copilot und der Data Agent innerhalb von Fabric. Die Antwort verliess die Plattform nicht.

OneLake in der Mitte. Rundherum die Workloads: Lakehouse, Warehouse, Real-Time Intelligence, Power BI, Data Factory.

Teil 1 · Was es gab

Seit Barcelona beantwortet Fabric auch Fragen von ausserhalb der Plattform: aus Copilot Chat, MCP-Clients und Foundry.

Vorher

Wir fragen Copilot in einem Power-BI-Bericht

  • Die Antwort bleibt in Fabric.
  • Die Daten gehen an einen Menschen, der auf den Bericht schaut.
Nachher

Agenten fragen Fabric von aussen

  • Die Fragen kommen aus Microsoft 365 Copilot Chat, aus MCP-Clients und aus Foundry.
  • Hauptabnehmer der Daten ist jetzt ein Agent.
Fabric ist nicht mehr nur der Ort, an dem wir Fragen stellen. Es ist jetzt eine Quelle, aus der Agenten ihre Antworten holen.

Teil 2 · Tür 1 von 3

Tür 1: Copilot Chat fragt ein semantisches Modell über Fabric IQ ab, im Namen des Benutzers.

GAFabric IQ in Copilot Chat und Cowork

Wir stellen in Copilot Chat eine Business-Frage, und die Antwort kommt aus einem semantischen Modell, das wir kontrollieren. Keine Zusatzkosten für KI-Tokens.

Konkret: Abfragen aus dem Chat verbrauchen weiterhin unsere Capacity. Es gibt nur keine separate Rechnung für Tokens.

Grenze: Die Antwort ist nur so gut wie die Beschreibungen und Synonyme im Modell. Die Version «Code Experience» kommt zuerst ins Frontier-Programm.

Teil 2 · Tür 2 von 3

Tür 2: Fabric IQ MCP liest nur. Core MCP kann deinen Tenant verändern: 15 seiner 27 Tools schreiben Änderungen.

GAFabric IQ MCP

Liest. Sechs Tools, alle nur lesend: Suche, Modellschema, DAX-Abfrage. Die Antwort kommt aus den Daten und respektiert die Berechtigungen des Benutzers.

TBCCore MCP

Ändert. 27 Tools, 15 davon schreiben Änderungen an Workspaces, Items und Berechtigungen. Anmeldung per OAuth 2.0 mit Entra ID, unterstützte Operationen landen im Audit-Log.

Learn, übersetzt: «Autonome oder falsch konfigurierte Clients können destruktive Aktionen ausführen.» Schutz davor ist in MCP nicht standardisiert, und Clients können Daten ausserhalb der Compliance-Grenzen von Fabric verarbeiten.

Teil 2 · Tür 3 von 3

Tür 3: der Data Agent als Tool in Copilot Studio und Delta-Tabellen, per REST gelesen.

TBCData Agents in Copilot Studio

Ein Data Agent aus Fabric arbeitet als Tool eines Agenten in Copilot Studio und zeigt in seiner Antwort eine Visualisierung.

Keynote: GA. Die Anleitung auf Learn nennt am 21. Oktober 2026 noch Preview. Auch Topics in Data Agents sind in Preview.

PREVIEWOneLake Table Read API

Eine App liest eine Delta- oder Iceberg-Tabelle per REST, und OneLake Security filtert Zeilen und Spalten bei jeder Anfrage.

Konkret: Jede App, die eine HTTP-Anfrage mit einem Entra-ID-Token schickt, kann die Tabelle lesen. Kein Spark-Cluster, kein SQL-Endpunkt, keine Kopie der Daten. Einziger Schutz sind die Berechtigungen in OneLake Security.

Teil 2 · Was gekommen ist

Osmos plant die Aufgabe, führt sie auf SparkCore aus und prüft das Ergebnis. Die Grenze bleiben die Berechtigungen in OneLake.

PREVIEWProject Osmos

Der Agent plant, erledigt und prüft eine Data-Engineering-Aufgabe in Fabric auf SparkCore. Wir starten ihn aus GitHub Copilot CLI, Claude Code oder Codex. Aufgaben bleiben bestehen, wir können später zu ihnen zurück.

Leitplanken: eine Berechtigungsgrenze, ein Schreibmuster, Regeln für Wiederholungen, Schema-Evolution. Die Berechtigungen in Fabric und OneLake bestimmen, was der Agent tun darf.

Teil 2 · Was gekommen ist

Die neue Ontologie in Fabric IQ: Entitäten aus dem semantischen Modell, Regeln in natürlicher Sprache, Export in einen Knowledge Graph.

PREVIEWOntologie in Fabric IQ

Wir bauen die Ontologie aus einem semantischen Modell, Daten in OneLake und Dokumenten. Regeln schreiben wir in natürlicher Sprache. DAX-Measures kommen als Metriken hinein. Der Ontologie-Agent handelt in unserem Namen und respektiert OneLake Security, RLS, OLS und CLS.

Konkret: Wir exportieren nach RDF und Turtle, den W3C-Standards für Knowledge Graphs, und importieren auch aus OWL. Ein anderes Graph-Tool kann eine Ontologie aus Fabric also öffnen.

Die bisherige Version der Ontologie verschwindet am 31. Januar 2027, die neue ersetzt sie. Eine unabhängige Analyse bemängelte Entitäten ohne identifizierenden Schlüssel und eine fehlende automatische Zustandsprüfung der Ontologie.

Rollen, RLS und CLS an einem Ort, auch über Shortcuts. Jedes Lakehouse bekommt eine Rolle DefaultReader. GA ist für die nächsten Wochen angekündigt, ohne konkretes Datum.

Teil 2 · Was gekommen ist

Policies (nur Allow), Catalog Govern und Observability: drei Bildschirme für Admins.

PREVIEWPolicies in Fabric

Geltungsbereich: Tenant oder Capacity. Es gibt nur eine Allow-Liste: Der einzige Effekt ist Allow, ein Deny gibt es nicht. Bedingungen: Workspace, Gruppen, Vertraulichkeitsbezeichnungen, Domäne des Empfängers, Item-Typ.

GAOneLake catalog Govern

Ein Bildschirm für Admins: Abdeckung mit Bezeichnungen, DLP-Ergebnisse, Tenant-Einstellungen, empfohlene Massnahmen.

Die Daten werden einmal täglich aktualisiert. Tabellen innerhalb von Items deckt die Ansicht nicht ab.

PREVIEWObservability

Der neue Monitor Hub: Laufhistorie und Erfolgsquote für jeden Job. Dazu Workspace Monitoring in einem Eventhouse und Alerts mit Activator.

PREVIEWOneLake catalog search API

POST /v1/catalog/search sucht nach Name, Beschreibung und Workspace-Name, mit Filter nach Typ. Zurück kommt nur, wofür wir Berechtigungen haben. Das Tool search_catalog in Core MCP führt dieselbe Suche aus.

GAOneLake table APIs

Der Endpunkt onelake.table.fabric.microsoft.com: Delta über eine mit Unity Catalog kompatible API, Iceberg über den Iceberg REST Catalog. Eine Delta-Tabelle aus dem Lakehouse erscheint als Iceberg format-version 2.
