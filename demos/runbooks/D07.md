# D07. Operations agent investigates a failed pipeline

![PREVIEW](https://img.shields.io/badge/PREVIEW-B85C00?style=flat-square) Slide 14 · Recording: [English](../../en/media/S11-A6-operations-agent.mp4) · [Polish](../../pl/media/S11-A6-operations-agent.mp4) · [German](../../de/media/S11-A6-operations-agent.mp4)

The operations agent reads the failed run from Monitor hub and explains the root cause. It is read-only and changes nothing.

## You need

- The pipeline `pl_daily_trials_load` from `up`. It fails on purpose: its landing file never arrives.
- Workspace monitoring on, and the Contributor role or higher.

## Steps

1. In the workspace, open **Workspace settings** > **Monitoring** and turn on monitoring. Wait until the monitoring eventhouse exists.
2. Run the pipeline again so the failure lands in monitoring: `python3 fabdemo.py pipeline`.
3. Open **Monitor hub** > **Job runs**, find `pl_daily_trials_load`, and select **Investigate**.
4. Read the report: what failed, the timeline, the likely root cause, and next steps.

## Expected result

The agent names the notebook activity, the missing file `Files/landing/trials/2026-10-18/preference_trials_daily.csv`, and proposes checking the upstream delivery before a rerun.

## Time and cost

About 5 minutes. Runs on the F8 capacity from `up`.
