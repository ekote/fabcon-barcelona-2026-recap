Część 2 · Drzwi 1 z 3

Drzwi 1: Copilot Chat odpytuje model semantyczny przez Fabric IQ w imieniu użytkownika.

GAFabric IQ w Copilot Chat i Cowork

Zadajemy pytanie biznesowe w Copilot Chat, a odpowiedź przychodzi z modelu semantycznego, nad którym mamy kontrolę. Bez dodatkowych opłat za tokeny AI.

Czyli: zapytania z czatu nadal zużywają naszą capacity. Nie ma tylko osobnego rachunku za tokeny.

Ograniczenie: odpowiedź jest tak dobra, jak opisy i synonimy w modelu. Wersja „code experience” trafi najpierw do programu Frontier.

Część 2 · Drzwi 2 z 3

Drzwi 2: Fabric IQ MCP tylko czyta dane. Core MCP może zmieniać tenant: 15 z 27 jego narzędzi zapisuje zmiany.

GAFabric IQ MCP

Czyta. Ma 6 narzędzi, wszystkie tylko do odczytu: wyszukiwanie, schemat modelu, zapytanie DAX. Odpowiedź pochodzi z danych i respektuje uprawnienia użytkownika.

TBCCore MCP

Zmienia. Ma 27 narzędzi, 15 z nich zapisuje zmiany w workspace'ach, elementach i uprawnieniach. Logowanie przez OAuth 2.0 z Entra ID, każda operacja trafia do logu audytu.

Cytat z Learn, w tłumaczeniu: „klienci autonomiczni lub źle skonfigurowani mogą wykonać operacje destrukcyjne, MCP nie ma standardowego zabezpieczenia, a klient może przetwarzać dane poza granicą zgodności Fabric”.

Część 2 · Drzwi 3 z 3

Drzwi 3: data agent jako narzędzie w Copilot Studio i odczyt tabel Delta przez REST.

GAData agenty w Copilot Studio

Data agent z Fabric działa jako narzędzie agenta w Copilot Studio i w odpowiedzi pokazuje wizualizację.

Tematy (topics) w data agentach są jeszcze w preview.

PREVIEWOneLake Table Read API

Aplikacja czyta tabelę Delta albo Iceberg przez REST, a OneLake security filtruje wiersze i kolumny przy każdym zapytaniu.

Czyli: tabelę przeczyta każda aplikacja, która wyśle zapytanie HTTP z tokenem Entra ID. Bez klastra Spark, bez SQL endpointu, bez kopii danych. Dostępu pilnują wyłącznie uprawnienia OneLake security.

Część 2 · Co dojechało

Osmos sam planuje zadanie, uruchamia je na SparkCore i sprawdza wynik. Granicą pozostają uprawnienia OneLake.

PREVIEWProject Osmos

Agent planuje, wykonuje i sprawdza zadanie inżynierskie w Fabric na SparkCore. Uruchamiamy go z GitHub Copilot CLI, Claude Code albo Codex. Zadania są trwałe, można do nich wrócić.

Zabezpieczenia: granica uprawnień, wzorzec zapisu, zasady ponownego uruchomienia, ewolucja schematu. Uprawnienia Fabric i OneLake wyznaczają, co agent może zrobić.

Część 2 · Co dojechało

Agent operacyjny tylko czyta dane z Monitor hub. Agentów baz danych jeszcze nie ma.

PREVIEW

Agent analizuje przyczynę nieudanego uruchomienia pipeline'u prosto z Monitor hub.

Działa tylko do odczytu, w imieniu zalogowanego użytkownika. Wymaga roli Contributor i włączonego workspace monitoring.

ROADMAPAAgenci baz danych

Dla SQL i PostgreSQL, w Database Hub i w VS Code. Zapowiedziane na keynote, jeszcze niedostępne.

Część 2 · Co dojechało

Nowa ontologia w Fabric IQ: encje z modelu semantycznego, reguły w języku naturalnym, eksport do grafu wiedzy.

PREVIEWOntologia w Fabric IQ

Ontologia powstaje z modelu semantycznego, danych w OneLake i dokumentów. Reguły piszemy w języku naturalnym. Miary DAX trafiają do niej jako metryki. Agent ontologii działa w naszym imieniu i respektuje OneLake security, RLS, OLS i CLS.

Czyli: eksportujemy do RDF i Turtle, standardów W3C dla grafów wiedzy, a importujemy także z OWL. Ontologię z Fabric otworzy więc inne narzędzie grafowe.

Dotychczasowa wersja ontologii znika 31 stycznia 2027, nowa ją zastępuje. Niezależna analiza wytknęła encje bez klucza identyfikującego i brak automatycznej kontroli stanu ontologii.

Część 2 · Co dojechało

Polityki (tylko allow), catalog Govern i observability: trzy ekrany administratora.

PREVIEWPolityki w Fabric

Zakres: tenant albo capacity. Działa tylko lista dozwolonych: jedynym efektem jest Allow, a Deny nie istnieje. Warunki: workspace, grupy, etykiety wrażliwości, domena odbiorcy, typ elementu.

GAOneLake catalog Govern

Jeden ekran dla admina: pokrycie etykietami, wyniki DLP, ustawienia tenantu, zalecane działania.

Dane odświeżają się raz dziennie. Widok nie obejmuje tabel wewnątrz elementów.

PREVIEWObservability

Nowy Monitor hub: historia przebiegów i odsetek udanych uruchomień każdego joba. Do tego workspace monitoring w eventhouse i alerty Activator.

PREVIEWOneLake catalog search API

POST /v1/catalog/search szuka po nazwie, opisie i nazwie workspace'u, z filtrem typów. Zwraca tylko to, do czego mamy uprawnienia. To samo wyszukiwanie daje narzędzie search_catalog w Core MCP.

Czyli: agent najpierw sprawdza, czy model albo tabela już istnieje, zanim zbuduje kolejną kopię.

AI functions w Sparku: tłumaczenie, sentyment i klasyfikacja jedną linijką na kolumnę.

GAAI functions w notebooku PySpark

ai.translate, ai.analyze_sentiment i ai.classify na komentarzach testerów napisanych po angielsku, arabsku i francusku. Wbudowany endpoint Fabric, bez klucza API.

Materialized lake views: architektura medalionowa w SQL, reguły jakości w definicji widoku.

GAMaterialized lake views

Warstwy srebrną i złotą tworzymy przez CREATE MATERIALIZED LAKE VIEW. Fabric sam buduje lineage i odświeża widoki w kolejności zależności. CONSTRAINT … ON MISMATCH DROP odrzuca błędne wiersze.

Czyli: trzy błędne wiersze z panelu nie trafiły do warstwy złotej. Raport przebiegu pokazuje Dropped rows: 3.

Widoki tworzone z PySpark są w preview i odświeżają się tylko w całości.
