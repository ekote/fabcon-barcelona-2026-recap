Part 1 · What we had

After Barcelona, Fabric also answers questions from outside the platform: from Copilot Chat, MCP clients, and Foundry.

Before

We ask Copilot in a Power BI report

  • The answer stays in Fabric.
  • The data goes to a person looking at the report.
After

Agents query Fabric from the outside

  • Questions come from Microsoft 365 Copilot Chat, MCP clients, and Foundry.
  • The main consumer of the data is now an agent.

Part 2 · Door 1 of 3

Door 1: Copilot Chat queries a semantic model through Fabric IQ on the user's behalf.

GAFabric IQ in Copilot Chat and Cowork

We ask a business question in Copilot Chat, and the answer comes from a semantic model we control. No extra charge for AI tokens.

In practice: queries from the chat still use our capacity. There's just no separate bill for tokens.

Limit: the answer is only as good as the descriptions and synonyms in the model. The “code experience” version goes to the Frontier program first.

Part 2 · Door 2 of 3

Door 2: Fabric IQ MCP only reads data. Core MCP can change your tenant: 15 of its 27 tools write changes.

GAFabric IQ MCP

Reads. Six tools, all read-only: search, model schema, DAX query. The answer comes from the data and respects the user's permissions.

TBCCore MCP

Changes. 27 tools, and 15 of them write changes to workspaces, items, and permissions. Sign-in uses OAuth 2.0 with Entra ID, and Fabric logs supported operations in the audit log.

Learn: “Autonomous or misconfigured clients may perform destructive actions.” Safeguards against destructive operations aren't standardized in MCP, and a client can process data outside Fabric's compliance boundaries.

Part 2 · Door 3 of 3

Door 3: the data agent as a tool in Copilot Studio, and Delta tables read over REST.

TBCData agents in Copilot Studio

A Fabric data agent works as a tool for an agent in Copilot Studio and shows a visualization in its answer.

Keynote: GA. The Learn walkthrough still says preview on October 21, 2026. Topics in data agents are in preview too.

PREVIEWOneLake Table Read API

An app reads a Delta or Iceberg table over REST, and OneLake security filters rows and columns on every request.

In practice: any app that sends an HTTP request with an Entra ID token can read the table. No Spark cluster, no SQL endpoint, no copy of the data. OneLake security permissions are the only guard.

Part 2 · What shipped

Osmos plans the task, runs it on SparkCore, and checks the result. OneLake permissions remain the boundary.

PREVIEWProject Osmos

The agent plans, runs, and validates a data engineering task in Fabric on SparkCore. We start it from GitHub Copilot CLI, Claude Code, or Codex. Tasks persist, so we can come back to them.

Guardrails: a permission boundary, a write pattern, rerun rules, schema evolution. Fabric and OneLake permissions decide what the agent can do.

Part 2 · What shipped

The new ontology in Fabric IQ: entities from the semantic model, rules in natural language, export to a knowledge graph.

PREVIEWOntology in Fabric IQ

We build the ontology from a semantic model, data in OneLake, and documents. We write rules in natural language. DAX measures come in as metrics. The ontology agent acts on our behalf and respects OneLake security, RLS, OLS, and CLS.

In practice: we export to RDF and Turtle, the W3C standards for knowledge graphs, and we can import from OWL. Another graph tool can open an ontology from Fabric.

The previous ontology version goes away on January 31, 2027, and the new one replaces it. An independent review flagged entities without an identifying key and no automatic health check for the ontology.

Part 2 · What shipped

Policies (allow only), catalog Govern, and observability: three admin screens.

PREVIEWPolicies in Fabric

Scope: tenant or capacity. It's an allow list only: the only effect is Allow, and there's no Deny. Conditions: workspace, groups, sensitivity labels, recipient domain, item type.

GAOneLake catalog Govern

One screen for the admin: label coverage, DLP results, tenant settings, recommended actions.

The data refreshes once a day. The view doesn't cover tables inside items.

PREVIEWObservability

The new Monitor hub: run history and success rate for every job. Plus workspace monitoring in an eventhouse and Activator alerts.

Appendix · New features in action

Searching the OneLake catalog from code: one query, the whole tenant.

PREVIEWOneLake catalog search API

POST /v1/catalog/search searches by name, description, and workspace name, with a type filter. It returns only what we have permission to see. The search_catalog tool in Core MCP runs the same search.

In practice: an agent first checks whether a model or table already exists, before it builds another copy.

010203
Appendix · New features in action

AI functions in Spark: translation, sentiment, and classification in one line per column.

GAAI functions in a PySpark notebook

ai.translate, ai.analyze_sentiment, and ai.classify on tester comments written in English, Arabic, and French. Built-in Fabric endpoint, no API key.

In practice: we process text where the data lives, with no separate service and no copying.

On Runtime 2.0 you have to name the model explicitly for now. Learn documents this as a temporary workaround.

010203
Appendix · New features in action

Materialized lake views: a medallion architecture in SQL, with quality rules in the view definition.

GAMaterialized lake views

We create the silver and gold layers with CREATE MATERIALIZED LAKE VIEW. Fabric builds the lineage and refreshes views in dependency order. CONSTRAINT … ON MISMATCH DROP rejects bad rows.

In practice: three bad rows from the panel never reached the gold layer. The run report shows Dropped rows: 3.

Views created from PySpark are in preview and only do full refreshes.

Appendix · New features in action

The data agent: a question, SQL on the lakehouse, a one-line answer and a table.

GAFabric data agent

An agent on lh_oud_rd with instructions in English. Both answers match the data: OB-104 Oud Saffron S-7, 68%, 14,353 QAR per kilogram.

In practice: we test the agent with questions we already know the answer to.

With the vaguer question “Which formula beats the reference most often?”, the agent counted winning trials and named the wrong formula. Each formula has only about one trial.

Appendix · New features in action

We see the same Delta tables through the Unity Catalog API and the Iceberg REST Catalog.

GAOneLake table APIs

The onelake.table.fabric.microsoft.com endpoint: Delta through a Unity Catalog compatible API, Iceberg through the Iceberg REST Catalog. A Delta table from the lakehouse shows up as Iceberg format-version 2.

In practice: any engine that speaks Iceberg REST or Unity Catalog sees our tables with no copy and no export.
